# ATOM: air-theme-flip — хром завжди належить секції під ним (per-section theme)

> Закон руху, НЕ сніпет. Ролі абстрактні: section×N (кожна несе тему) / chrome (хедер + будь-який fixed-UI) / overlay (меню з власною темою).
> Джерела: AIR T-501 (11 themed-секцій `data-themed-class="ui-light|ui-dark"`) + A-18 (хедер transition 1.2s)
> з D_AIR_video/D_AIR_architecture; движок-родич: `award-re-plugin/library/components/theme-tween` (EVER, var-lerp).
> 🧪 **CD-ТРІАЛ 2/2 (рада #4):** BUILD цього атома робить Claude Design з промпта, згенерованого з ЦЬОГО SPEC-а.
> Гейти на RAW output. Лог часу в SOURCE-TRIAL.md.

## СУТЬ (одне речення)
Кожна секція несе свою тему (палітру), а весь хром — хедер, фон сторінки, ink, акценти, плаваючі елементи —
ЗАВЖДИ належить секції, що зараз під лінією хедера: на перетині країв секцій хром плавно перефарбовується
за 1.2s, лише кольорові властивості, жодного layout/transform.

## ЧОМУ ЦЕ ПРАЦЮЄ
Ритм світла = ритм актів (AIR чергує 11 світлих/темних секцій — сторінка дихає). Хром, що завжди збігається
з тим, що під ним, робить сайт «одним фільмом»; плавний tween (не hard flip) — межа секцій не б'є по оку.

## МЕХАНІКИ
- **M1 розмітка**: секція оголошує тему data-атрибутами (мінімум bg+ink+accent; AIR-випадок = 2 пресети light/dark).
- **M2 детекція активної**: reference-точка = ЛІНІЯ ХЕДЕРА (низ fixed-хедера); активна секція = та, чиї межі
  містять цю лінію (rAF/scroll-check або IO). НЕ центр екрана — хедер мусить збігатися з тим, що фізично під ним.
- **M3 закон перефарбування**: color-props ONLY (background-color/color/border-color/fill/CSS-vars);
  тривалість **1.2s**, ease **cubic-bezier(.25,.74,.22,.99)**. Реалізація AIR = class-flip + CSS transition;
  еквівалент EVER = rAF-lerp CSS-vars (theme-tween). Закон один: перехід ПЛАВНИЙ — mid-значення лежить МІЖ темами.
- **M4 пріоритет оверлея**: відкрите меню/модалка накидає ВЛАСНУ тему на хром поверх секційної; close повертає секційну.
- **M5 фон сторінки/секцій** themed так само — не лише хедер (сторінковий ритм світла).
- **M6 reduced-motion**: snap до активної теми без tween.
- **M7 mobile (390×844)**: механіка та сама (scroll → `--bg` swap по хедер-лінії) — ✅ перевірено S37 playwright:
  `--bg` реально свапається по скролу на touch. НІЧОГО не заглушено. Для hero-фасаду передати AIR-пресети
  (світлий акт `#f4efe6/#fafafa` + ink `#0a0a0a` → темний акт `#0a0a0a` + ink `#f4efe6`) — build.html зараз несе
  LAGUNA-палітру (dawn-sand), це ФАСАД-параметр (M1: «конкретні палітри — параметри ролі»), не зміна руху.

## COUPLING / SCROLL-WINDOW
Тригерний по порогах (перетин межі секції з хедер-лінією), НЕ scrub: темп фіксований у 1.2s-transition.
Вікно = момент перетину; напрямок неважливий (працює однаково вгору/вниз).

## ІНВАРІАНТИ ЗАКОНУ
1.2s + ease `.25,.74,.22,.99`; color-only (нуль transform/layout у transition); детекція по хедер-лінії;
mid-значення між темами (tween, не flip); overlay-пріоритет. Кількість секцій, конкретні палітри,
світлий/темний чи довільні кольори — параметри ролі/фасаду.

## TRANSFER-ГЕЙТ (acceptance, ганяти числами)
1. N≠11 секцій з ДОВІЛЬНИМИ палітрами (не ч/б AIR) — активна тема правильна на всіх порогах хедер-лінії.
2. Mid-семпл під час переходу: колір хедера МІЖ старою і новою темою (tween доведено).
3. transition-property хрому не містить layout/transform-props.
4. Відкриття оверлея перефарбовує хром у тему оверлея; закриття повертає секційну.
5. 0 console-errors; reduced-motion = snap.

## ХОРЕО-ЗВІРКА З ЖИВИМ (С32, `Desktop-air.mp4` 15fps сигнал-стата 26-34s)
Люмінанс лого-зони при межі світле→темна карта (~26.5s): стрибок 189→101 за ~0.3s і РІВНО в момент
проходу краю секції під хедером → закон «фліп на перетині хедер-лінії» ПІДТВЕРДЖЕНО живим записом.
Тривалість tween-а з запису НЕ витягується (крива домінується проїздом краю секції, гліф лого замалий
у кадрі) — 1.2s лишається з CSS live-teardown A-18 (авторитетніше за пікселі). Фінальне око — по запису Єгора.
