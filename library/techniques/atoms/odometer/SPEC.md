# ATOM: odometer — scene-counter roll (springs 3→9→16)

> Закон руху, НЕ сніпет. Ролі абстрактні: bg-media / card / photo / counter / label.
> Джерела: SOURCE.md (плівка + live markup + capture.json). Статус наративу Єгора: PENDING — v1 зі спостережень.

## СУТЬ (одне речення)
N повноекранних сцен (bg-media + card[photo+counter+label] на одному місці лейауту) змінюються всередині ОДНОГО pinned-band'а **єдиною wipe-up межею, скрабленою скролом**: кожен елемент передається наступній сцені В МОМЕНТ, коли межа проходить його висоту на екрані — жодних окремих fade/slide-твінів.

## ЧОМУ ЦЕ ВІДЧУВАЄТЬСЯ ЯК ОДОМЕТР
Counter-гліфи всіх сцен складені стосом на одній позиції; reveal-межа, піднімаючись, «прокочує» стару цифру в нову (низ card = цифра+label → свапаються ПЕРШИМИ; фото вище → свапається ПІЗНІШЕ). Порядок = ЕМЕРДЖЕНТНИЙ від геометрії, не задається окремими анімаціями.

## МЕХАНІКИ
- **M1 pin-band**: sticky-контейнер висотою (N+1)·100vh; шар pinned; p = пройдено/(N·vh). N=3 → hold 300vh.
- **M2 stack**: всі сцени абсолютно стаковані, ідентична геометрія card-слота (у springs: col-3 праворуч від центру, photo зверху, h0-serif counter під ним, label малими капсами).
- **M3 reveal-закон** (транзиція k у вікні Wk ≈ 1vh скролу; W1=[0..⅓], W2=[⅓..⅔] band'а, останні ⅓ = hold):
  - card-item сцени k+1: `clip-path: polygon(0% Y,100% Y,100% 100%,0% 100%)`, Y: 100%→0% лінійно по Wk (reveal знизу, ITEM-простір);
  - bg-media сцени k+1: та сама wipe-up межа на повний екран, завершує за ~перші 55% Wk (швидша за item);
  - вхідне медіа: `scale 1.2→1.0` через Wk і далі (повільний settle, Ken Burns);
  - counter+label НЕ анімуються самі — їх «ролить» межа.
- **M4 drift**: card-колонка повільно дрейфує вгору весь band (~3-5% швидкості скролу) — сцена жива, не заморожена.
- **M5 вхід/вихід секції**: попередня/наступна секція накривається/накриває через sticky--under-next (це ОКРЕМИЙ атом wipe-up scene-transition, тут не дублюється).

## ТЕМП (з живої плівки, скрол Єгора — нелінійний!)
