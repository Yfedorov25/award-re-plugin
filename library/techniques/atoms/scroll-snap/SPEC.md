# ATOM: scroll-snap — магніти на скрол-треку поверх Lenis (v1)

## СУТЬ
Снап-точки springs: позиції на СКРОЛ-ТРЕКУ (не CSS scroll-snap). Коли інпут користувача стих і
швидкість мала — скрол СКОВЗАЄ до найближчої точки через lenis.scrollTo тим самим годинником;
увесь scrub-контент просто дограє до стану спокою. Снап ніколи не анімує контент — тільки
позицію скролу. Користувач завжди перемагає: новий інпут скасовує glide.

## МЕХАНІКИ (SERVED MARKUP home ×20 інстансів; плівка цей закон не показує)
- M1 ФОРМАТ ТОЧКИ: `{viewport: V, element: E}` = вирівняти точку V viewport-а з точкою E
  елемента (E у % висоти viewport від старту елемента). На home всі V=0 (топ).
- M2 СТАНЦІЇ BAND-ІВ: багатоточкові списки (100/200/300/400) = hold-и сцен усередині довгих
  pinned band-ів (одометр ×4, wellness ×2 тощо). Одноточкові (element 100) = точка «сцена
  повністю прибула» для sticky-секцій; element 0 = топ секції.
- M3 АРМІНГ (гіпотеза, з UX-стандарту): інпут idle ~150ms + |velocity| < поріг → пошук
  найближчої точки в радіусі захоплення ~±35vh → lenis.scrollTo(~0.9s, expo-out). Поза
  радіусом — вільний скрол легальний (мертві зони між магнітами).
- M4 СКАСУВАННЯ: будь-який новий інпут під час glide зупиняє снап миттєво; швидкий прохід повз
  точки не захоплюється.
- M5 ІНВАРІАНТ: під час glide жодних паралельних твінів контенту — все їде своїми scrub-вікнами.
- M6 РЕВЕРС: магніти двонаправлені.
