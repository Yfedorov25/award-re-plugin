# PRICE - база секції ЗАКРИТА: 3 прототипи-дерева + 3 консолі (2026-07-03)

Секція «Інвестиційна пропозиція». Ядро = інтерактивні калькулятори дохідності, зібрані
в ПРОТОТИПИ-ДЕРЕВА (розвилка наміру, всередині листів живуть повні award-композиції).
Галерея: all-prototypes.html (десктоп rail + iframe). Мобільної версії поки нема (десктоп-first).

## Ключове розрізнення (урок F-55/F-56)
- КОМПОЗИЦІЯ = один стан/сцена (крива, оренда, розтермінування). Це те, що робить Claude Design.
- ПРОТОТИП = НАБІР композицій, зібраний у дерево з розвилками. Це збирає головний агент з коду,
  переносячи РЕАЛЬНІ композиції 1-в-1 (не переписуючи спрощені).

## Прототипи-дерева (p-1..p-3)
- **price-1-tree-town** - глибина 2, асиметрична: «Купую щоб жити» -> розтермінування (лист);
  «Купую щоб інвестувати» -> підрозвилка «Здавати» (оренда, band-pick, окупність) + «Перепродати»
  (крива зростання ціни метра 900->1200 $/м², monotone-spline + LUT-вістря + band-коридор).
- **price-2-tree-smart** - той самий каркас + ЧІП ПЛОЩІ 24/27 м², що керує ВСІМА числами
  (площа -> ціна -> вхід -> платіж -> прибуток). Інвест = ТІЛЬКИ «Перепродати» (крива 950->1150):
  оренди в фактажі ЖК немає, тому гілки «Здавати» немає (asset-truth, рішення власника).
- **price-3-tree-commerce** - глибина 1 (комерція = бізнес-актив, без наміру «жити»). Одна
  композиція: крива перепродажу 1100->1430 (рівно +30% капіталізації), слайдер блоку 100-200 м²,
  прибуток масштабується з площею. Смуга показує ринок готового 1400-1700.

## Консолі-розвилки (p-4..p-6, half-step)
- **price-4-branch-town / price-5-branch-smart / price-6-branch-commerce** - C-гібрид консолі:
  одна двоколонка (індекс+таби / вікно), render(branch), reveal IN PLACE, кнопка розгортає повну
  cinema-сцену inline. Простіша дворозвилка без другого рівня. Лишені як приклад проміжного кроку.

## Архітектура дерева (канон)
```
ПРОТОТИП «Інвестиція в X»
- L1 «Купую щоб жити»       (глибина 1, лист)  -> розтермінування
- L1 «Купую щоб інвестувати» (глибина 2)
    - L2 «Здавати»    -> оренда-сцена (тільки town: є ставка 550-700)
    - L2 «Перепродати» -> крива зростання ціни метра
```
Асиметрія навмисна (жити=1 лист, інвестувати=2). Макс 2 рівні; 3 рівні заборонені.
Консоль БЕЗ піна (фікс tw-3/F-54: два піни -> offsetHeight=0 -> ділення на нуль).

## Дедуп (P0)
Один `PriceModel` (installment/entry/rentMonthly/payback/resaleGain/entryTotal) + один `makeOdo`
на файл. Композиції = функції mountInstallmentScene / mountRentScene / mountCurveScene.
Крива без піна -> ВЛАСНИЙ self-play драйвер (rAF-твін 0->1 за 1550ms), синхрон-інваріант той
самий: одометр = висота кінчика = priceAt(drawP), один драйвер.

## Synchron-інваріант кривої (F-52, святе)
Число під кінчиком МУСИТЬ дорівнювати висоті кінчика: `odo.set(priceAt(p))` і `#cTip cy = YOF(priceAt(p))`
з ОДНОГО p. priceAt = квантована-з-рампами (плато на реальних стадійних цінах + monotone-рампи),
нуль вигаданих проміжних значень. Верифай: bottomSpread=0, priceAt(0)=старт, priceAt(1)=здача, monotone.

## serif-одометр (ЗАКОН, вкусив 2×)
Rolling-digit у serif: клітинка `height=line-height=var(--ch:1.24em)` (запас під хвости 9/6/8),
`text-align:center`, НЕ flex-center (=стрибок базових ліній). Зсув `translateY(calc(var(--ch)*-n))`.
Easing без overshoot: roll cubic-bezier(.4,0,.2,1), settle cubic-bezier(.22,1,.36,1).
Верифай Playwright: Range.getBoundingClientRect кожної видимої цифри, bottomSpread=0 у спокої.

## Числа (демо, з правди сайтів - НЕ вигадані)
- town: пресейл 900 $/м², ціна 82×900=73 800, вхід 30%, оренда 550-700, окупність ~10р, крива 900->1200.
- smart: пресейл 950 $/м², вхід=перший внесок % (дефолт 40) від ціни площі×950, площі 24/27, крива 950->1150.
- commerce: пресейл 1100 $/м², крива 1100->1430 (=+30%), блоки 100-200 м², ринок готового 1400-1700.

## Копі-закон (Fedoriv)
Нуль em/en-dash у видимій копі. Просто, зрозуміло, число-герой. Жаргон (капіталізація/дельта/
при введенні) ТІЛЬКИ у службовому how-панелі «Як ми це рахували», ніколи на face.
