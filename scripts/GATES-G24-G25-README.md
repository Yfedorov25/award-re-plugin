# G24 BoardDiffGate + G25 TextOverlapGate — нові гейти «наше ↔ live» (S34, 2026-07-18)

Побудовані щоб ловити клас відмінностей, який **G18 (pixel-parity) і G22 (video-parity) НЕ бачать**
на AIR-фасад-репліках: композицію, розподіл маси, вирівнювання, і найголовніше — **налізання тексту**.
Причина сліпоти G18/G22: для AIR dummy-фасаду немає per-element answer-key (він springs-only,
[[g23-specgate-is-springs-only]]), а піксель-diff топиться в різниці роздільності+тону+хрому.

⚠️ **ЖОДЕН з цих гейтів НЕ доводить піксельну парність.** Зелений = «структура/налізання ок», НЕ
«виглядає 1-в-1». Фінальне слово про фасад — око Єгора по живому AIR ([[gate-green-not-done]]).

## ✅ G25 TextOverlapGate — ГОТОВИЙ, НАДІЙНИЙ (`scripts/text-overlap-gate.mjs`)

Ловить «текст налазить» (клас, який Єгор ловить оком) через **DOM getClientRects()**, не пікселі.
Для кожного текст-вузла бере bounding box; фіксує **вертикальне+горизонтальне перекриття** між
НЕспорідненими елементами (ancestor/descendant виключені). Нуль фолс-позитивів на великих
гліфах/вкладених спанах — на відміну від піксельних band-детекторів, які плутають великий шрифт із налізанням.

```
node scripts/text-overlap-gate.mjs --url <http> [--url <http2>...] [--selftest] [--out report.json]
```
- `--selftest`: рендерить кожен URL зі зламаним line-height/spacing; детектор МУСИТЬ спрацювати
  (доводить що він живий, а не мертвий-зелений). Провал self-тесту → exit 3.
- Вихід: `collisions=0` = PASS. Кожен overlap логується (текст A / текст B / px-перекриття).

**Доведено S34:** calc+resale обидва PASS (0 collisions), self-тест broken=16/12 (детектор живий).
Синтетично зламаний line-height → детектор впіймав налізання `~40%`/`Potential increase`.

**Роль:** інструмент-доказ (як element-gate для springs). Запускаю й посилаюсь на звіт, коли кажу
«нема налізання тексту». НЕ реєстрований як блокуючий Stop-хук (щоб не плодити крос-трек фолс-блоки).

(0.56 на ідентичному-зі-зсувом) → shift-tolerant + виведений з блокуючих (інформативний прапорець).
