# award-re — Constitution (hard rules for every command, skill, agent)

> Цей плагін будує award-сайти НЕРУХОМОСТІ рівня Vide Infra. Усі команди/skills/agents підкоряються цим правилам. Frontmatter — англійською (сумісність Claude Code), інструкції/тіло — українською.

## 1. МИ = CLONE VIDE INFRA
- Vide Infra (ERA, AIR, Springs, Silver Pinewood, Ever) = ЄДИНИЙ референс рівня й прийомів. Будуємо настільки ж award, продумано до дрібниць, де ВСЕ повʼязано.
- **Конкуренти клієнта = ТІЛЬКИ СЕНСИ** (ЦА/болі/позиціонування/чим відрізнятись). НІКОЛИ не копіюємо їхній візуал/прийоми/рівень.
- Кожен прийом — з бази знань (`skills/*/references/`, `_TECHNIQUE_REGISTRY`). Жоден прийом не вигаданий.

## 2. NO WebGL (хардова заборона)
- Жодного Three.js/WebGL/R3F. WebGL-прийоми VI → завжди no-WebGL переклад (canvas-2D frame-scrub, inline-SVG, CSS, pre-rendered orbit).
- Текст завжди у DOM (= SEO), бо немає canvas-тексту.

## 3. СТРАТЕГІЯ ПЕРЕД ДИЗАЙНОМ
- НЕ «сайт заради сайту». Спершу `discovery` (research конкурентів=сенси + глибоке Fedoriv-інтерв'ю + позиціонування + бренд + копі) → `brief.md` + `brand.md` → і ТІЛЬКИ ПОТІМ дизайн.
- Сайт будується ПІД реальну ЦА/болі з brief, не за дефолтним шаблоном.

## 4. МОТИОН-ПАРТИТУРА НАПЕРЕД (лікує «кожна секція по-своєму»)
- ПЕРЕД побудовою секцій: зафіксувати ЄДИНІ КОНСТАНТИ (ОДИН ease під проєкт — НЕ глобальний; токени; scroll; reveal; медіа-обробка; типографіка) + розкласти ПАРТИТУРУ (прийом на кожну секцію + тема + темп + звʼязок) → `motion-score.md`.
- Секції будуються СТРОГО за партитурою, не імпровізуються. Тема перетікає dark↔light, естафета між секціями.

## 5. ВАРІАНТИ-ПРОТОТИПИ
- Для ключових секцій показати 2-4 перевірені VI-варіанти (з `_TECHNIQUE_REGISTRY`) + візуалізувати (текст/мокап/HTML-прототип) → user обирає → motion-score.md. Не один шлях.

## 6. СТЕК = ВИБІР ПІД ЗАДАЧУ
- Next/React АБО vanilla+Barba+Locomotive (як VI) АБО інше — обрати найкращий спосіб під задачу. Константа лише: award-рівень VI + NO WebGL.

## 7. КОПІРАЙТ = FEDORIV
- Живі розмовні речення, як говорить Fedoriv, один-в-один. Довжина ВІЛЬНА (hero може бути ≤6 слів або повне речення — НЕ закривати круті варіанти). Генерувати КІЛЬКА варіантів → найсильніший.
- Заборонено AI-slop і кліше (фільтр `_ANTISLOP_ukrainian_hard`). ZERO em-dash. «Ялинки» лапки. Активний стан.

## 8. DECISION HIERARCHY
1. Прямі інструкції user (найвища) → 2. Дані проєкту/клієнта (brief/brand/config) → 3. AI-припущення (найнижча).
- НІКОЛИ не вигадувати ціни/факти/дати. Нема даних → блок прихований (не плейсхолдер). Цитувати джерело (PB/D-файл, дані клієнта).

## 9. ПЕРФОМАНС (бойова doctrine)
- Залізно плавний скрол > красивий LCP. НІКОЛИ: mix-blend-mode/backdrop-filter над скрол-поверхнею; CSS transition на scroll-driven props; стек easing (ОДИН смузер); forever-rAF без idle fast-path. Деталі: `skills/perf-doctrine/references/PB_performance.md`.

## 10. ТЕХНІЧНІ ПРАВИЛА ПЛАГІНА
- `config.yaml` (`.award-re/config.yaml`) = реєстратор стану (mode/project_type/brand/arc/resume). 3 режими: Autopilot/Guided/Direct.
- Skills = НЕВИДИМА бібліотека (`disable-model-invocation: true`). Команди їх READ-ають і виконують inline (НЕ через Skill-tool).
- НЕ хардкодити модель у skills frontmatter.
- Перед AskUserQuestion — порожній рядок-спейсер (щоб панель не перекривала контент).
- Тільки RE-ніша. Вузько й глибоко.
