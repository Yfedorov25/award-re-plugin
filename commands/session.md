# award-re — Session (мітка сесії)

Закріплює, ЯКА ця сесія, щоб маршрутизація задач з Telegram-бота працювала точно
(а не вгадуванням). Кнопки бота = СЕСІЇ; кожна сесія володіє своєю міткою.

## Неймінг-конвеншн міток
Коротка kebab-мітка = одна сесія (Claude-чат), може покривати кілька сайтів:
- **`web3`** — сесія 3 сайтів (smarts + nahirna + quadro)
- **`towns`** — сесія towns (окремий чат)
- **`control`** — сесія платформи control
- інші — за потреби, той самий стиль (короткі, kebab, стабільні).

## Що робить команда
1. **Запам'ятай мітку** з аргументу (напр. `web3`) на ВЕСЬ цей чат. Далі КОЖЕН
   «розгреби inbox» БЕЗ явної мітки = розгрібати саме цю. Це контекстна памʼять сесії,
   не файл (towns і web3 живуть в одному репо/папці, файл би конфліктував).
2. **Підтверди юзеру** одним рядком: «Сесія = `<мітка>`. Розгрібаю чергу цієї мітки.»
3. **Покажи поточну чергу цієї мітки** (read-only, не виконуй):
   `curl -s -X POST https://control-rose.vercel.app/api/bot/admin -d '{"action":"inbox","secret":"<S>","session":"<мітка>"}'`
   (`<S>` = CONTROL_BOT_SECRET; у memory control-system-build або /tmp/bot-secret.txt).
   Виведи список: `#id · project · «raw»`. Якщо порожньо — скажи що черга чиста.
4. Далі, коли юзер скаже «розгреби inbox» — виконуй РЕЖИМ INBOX з task.md, фільтр
   `session=<ця-мітка>`. Розгрібаєш лише свою мітку (+ `any`). Чужі мітки — НЕ чіпай.

## Зміна мітки
Якщо юзер задає нову мітку цією ж командою — перепиши памʼять на нову. Одна сесія —
одна активна мітка за раз.

## Важливо
- НЕ вгадуй мітку з гілки/контексту, якщо юзер задав явно — бери задану.
- Якщо юзер НЕ задав мітку жодного разу, а просить «розгреби inbox» — СПИТАЙ яка мітка
  (не здогадуйся; towns і web3 в одній папці — помилка дорога).
