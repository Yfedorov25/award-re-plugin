# ВЕРДИКТ РАДИ S47: де тече труба і план змін (5 радників + суддя, одноголосно)

> Повний сирий результат: `verdict-full-raw.json`. Факти: `facts.md`.
> Мій доказовий вимір справжньої механіки ivy: title-центроїд СТОЇТЬ (17.5→19.3% за 7с),
> текст-рядки 19→4→27 (= SWAP на місці), фото-верх стабільний ~40% (= картки STACK, нова накриває).
> КОД ЗАБОРОНЕНО до затвердження плану Єгором.

## ДЕ ТЕЧЕ ТРУБА (одноголосно, потрійна діра на Етапі 1)

1. **ДЖЕРЕЛО**: механіка виводиться ОКОМ зі статичного montage 0.5-0.7с, на якому strip/stack/swap
   принципово нерозрізнимі. Два вирішальні ВИМІРНІ питання (заголовок стоїть чи їде; стару картку
   накривають чи вона їде) не міряються. Інструмент (track.mjs) існував і довів swipe на promenade,
   але його застосування ДИСКРЕЦІЙНЕ, не гейтоване.
2. **КОНТУР**: самоузгоджене коло В КВАДРАТІ. Expectations пишуться з мого CHOREO, і навіть ПЕРЕЛІК
   активних детекторів обирає мій config (swipeStrip/wipe/mechanism) — автор помилки контролює і
   питання, і відповіді. Єдиний live-anchored вимір (surface-parity) — одномірний скаляр з
   дегенеративним PASS на cream. live-timeline фізично не розрізняє strip від stack.
3. **ЗАПОБІЖНИК**: борд-блокер Єгору тригериться САМООЦІНКОЮ впевненості того самого агента, що
   інтерпретував. Хибна інтерпретація за визначенням іде з хибною впевненістю: 0 спрацювань з 2.

Ratchet (баг → детектор того ж дня) математично програє: кожен фікс = вузький детектор МИНУЛОГО
класу в коді, а генератор помилок живе в РОЗБОРІ upstream від усіх детекторів. 5 фейлів поспіль,
кожен нового класу. Перший незалежний суддя структури руху сьогодні = око Єгора (найдорожча точка).

## ПЛАН (6 кроків, впорядковано; кожен ловить ОБИДВІ хибні ivy-ітерації)

1. **CHOREO-CLAIMS** (день 0, без нового коду двигунів): CHOREO мусить містити машиночитну таблицю
   «зона × вікно руху → вердикт» із ЗАКРИТОГО словника {STANDS / TRAVELS(dir,px) / COVERS /
   COVERED-BY / SWAPS-на-місці / FADES / ENTERS / EXITS / OTHER}, кожна клітинка з src=трек:число
   (НЕ «бачу на montage»). Плюс: клас механіки з закритого реєстру; для кожного переходу ≥2
   конкурентні гіпотези + «яке число вбиває яку альтернативу»; 100% вікон timeline покриті.
   OTHER/UNMEASURABLE = АВТОМАТИЧНИЙ борд-блокер (тригер більше НЕ самооцінка). Гейт: без валідної
   таблиці variants/*.html фізично не записується. Винятків для «простих» атомів НЕМАЄ.
2. **zone-track / motion-map v2** (Етап 0): машинний вимір per-зона {y(t), occludedFrac(t),
   contentHash(t)} → вердикти-кандидати STANDS/TRAVELS/COVERED/SWAPS/FADE/MEDIA/UNKNOWN + канал
   v_zone/v_scroll (0=pinned, 1=їде зі сторінкою). Зони декларуються вручну прямокутниками
   З LIVE-КАДРУ (не з нашого коду). UNKNOWN = fail-closed. Правильна відповідь лежить у файлі
   ДО написання CHOREO.
3. **structure-parity** (новий БЕЗУМОВНИЙ вимір self-check): той самий екстрактор по live-відео і
   по нашому render(p). Порівняння в EVENT-домені (механіко-токени зон, порядок подій, лічильники
   N карток/N SWAP/N COVER, velocity-ratio) — НЕ по пікселях, НЕ в time-домені (нелінійний темп).
   Поля skip не існує. ЄДИНИЙ вимір що розриває самоузгоджене коло: референт = live, не мої
   expectations. Ловить хибну механіку навіть якщо ТЗ і верифікатор помились однаково.
4. **Незалежний ТЗ-верифікатор** (схема Єгора, конкретизована; пробний статус 3-5 атомів): окрема
   сесія, КАРАНТИН від CHOREO/SPEC автора; спочатку ВЛАСНІ виміри zone-track (власні числа ДО
   знайомства з чужими), потім машинний diff двох таблиць; будь-який diff = борд-блокер.
   CONFIRMED без власного числа = невалідний формат (вшито в схему). Обсяг lite: трек-числа +
   10-20 вирішальних кадрів (НЕ «сотні кадрів» — це масштабування методу що двічі провалився).
5. **Клас механіки визначає LIVE, не авторський config**: машинна класифікація з motion-map live →
   реєстр обов'язкових детекторів вмикається АВТОМАТИЧНО; config може лише ДОДАВАТИ. Розбіжність
   «клас з live vs клас у config» = FAIL до всіх інших вимірів. (Закриває глибшу половину діри:
   автор контролював ПИТАННЯ, не тільки відповіді.)
6. **Ratchet v2 — калібрація рівня ІНТЕРПРЕТАЦІЇ**: calibrate.mjs + 2 класи еталонів:
   НЕГАТИВНІ (архівні ivy іт.1/іт.2, wellness-crossfade, promenade-скрим МУСЯТЬ FAIL проти live) і
   ПОЗИТИВНІ (прийняті wellness/promenade МУСЯТЬ PASS). Правило назавжди: «вимір що не валить
   старі провали — не вимір». ivy іт.1/іт.2 стають довічними інжекторами.

## КРИТЕРІЙ «ТРУБА ЗАЛАТАНА» (вікно = наступні 3 атоми, все одночасно)

(1) ретро-калібрація зелена (structure-parity валить архівні провали, пасить еталони);
(2) механіко-класових зауважень ока Єгора = 0 на 3 атомах поспіль;
(3) ітерацій ока на атом ≤1 в середньому (зараз 2-7);
(4) guard проти process-bloat: повний цикл атома ≤2.5-3 год;
(5) false-блокерів <50% (кожен борд або реальна неоднозначність, або веде до калібрування порогів).

## ЧОГО НЕ РОБИТИ (відкинуто радою)

- N незалежних перевірок РЕАЛІЗАЦІЇ: помилка ЖОДНОГО разу не народжувалась у реалізації.
- Верифікатор-рецензент чужого тексту: correlated blindness; валідний лише diff незалежних ЧИСЕЛ.
- Ще один вузький ретроспективний детектор під ivy.
- Ручка «простий атом → скорочений шлях»: самооцінка складності і є коренем.
- Піксельне або time-домен порівняння live↔наш (нелінійний темп дасть false-FAIL → гумовий штамп).
- «Сотні кадрів × 2 агенти» буквально: числа диференціюють механіки, око — ні.
- Автосегментація зон у v1 (зони вручну з live-кадру).
- Вважати зелений structure-parity за «правильно»: він сертифікує КЛАС механіки і порядок подій;
  кегль/дизайн/кольори — інші виміри; око Єгора лишається фінальним суддею.

## РОЗБІЖНОСТІ НА РІШЕННЯ ЄГОРА

1. **Мікро-борд механіки ПЕРЕД кодом** (1 хв Єгора на атом: «клас механіки + 3 пари кадрів-доказів,
   так/ні»): найкращий ROI (хвилина проти 2 циклів по ~2 год), АЛЕ витрачає увагу Єгора і
   суперечить курсу на автономію. Рекомендація судді: увімкнути ТИМЧАСОВО на перші 3 атоми
   (поки structure-parity не пройде ретро-калібрацію), потім sunset.
2. **Статус верифікатора**: постійна роль vs пробна з sunset після 3-5 атомів. Рекомендація судді:
   пробний статус із метрикою, не віра.
3. **Масштаб інструмента кроку 2**: повний motion-map (2-3 дні) vs мінімальний зонний трек
   (~1 сесія). Рекомендація судді: мінімальна версія першою, розширення лише якщо калібрація
   на 5 архівних багах покаже недостатність.

## ЗМІНИ ATOM-PROTOCOL (конспект; повний список у verdict-full-raw.json → protocol_changes)

Етап 0: live-timeline → motion-map v2 (per-зона вердикти). Етап 1 розщепити на 1a (ТЗ-агент,
CLAIMS-таблиця) і 1b (верифікатор, карантин, власні числа, TZ-VERDICT.json). Тригер борд-блокера
переписати на об'єктивні умови. Етап 4: числа лише з CONFIRMED-claims; детектори замовляє live.
Етап 5: structure-parity у 🔒-виміри. Гейти: live-first-gate v2 (без CLAIMS+VERDICT html не
записується), inputsHash включає CLAIMS/VERDICT/треки, хук перевіряє session-id 1a ≠ 1b.
Етап 6: калібрація з негативними+позитивними еталонами.
