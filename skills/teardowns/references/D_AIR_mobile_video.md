- Frosted-glass картки (T-M17/T-M18) = backdrop-filter: за законом D2 НЕ класти над
  канвасом/скрабленою поверхнею — у нас лише над статичним фото, або щільний rgba-tint.

  придатний для «розстрочка/іпотека» кейсів (A-20), дисклеймер обов'язковий.

  геометрію в DOM.
- Read-only пресети замість слайдерів на моб = менше тач-конфліктів зі скролом —
  узгоджується з C7/B10; фінальна перевірка тач-плавності = реальний девайс.
- Сервіс-картки з ✛ без записаного розкриття — НЕ переносити «по пам'яті» механіку
  розкриття, поки не знято (C17/C18: тільки задокументовані прийоми).

## Р2.6 ОБМЕЖЕННЯ ПЕРЕНОСУ В RE (додатково до §10)
- Blur-reveal (T-M23) — дешевий (filter: blur + opacity), але НЕ на скрабленому канвасі (D2);
  для тексту обмежити 2–3 рівнями розмиття, інакше мильно на LCD.
- POI-картки (T-M26): хвилини/км ТІЛЬКИ з реальної маршрутизації (F-8/OSM), пунктир =
  SVG stroke-dashoffset по реальній геометрії вулиць; drive-підсвітка = окремий шар доріг.
- Funnel-штора (T-M29) — один ритуал на сайт (C9): чорна wordmark-штора лише для входу
  у фунел, решта переходів — швидка біла (T-M22).
- Заглушка T-M32 — для RE НЕ копіювати «only on desktop» дослівно: наш дріл (A-03) має
  мобільну LIST-заміну одразу, заглушка лише для multi-select органів керування.
- Favourites-email (T-M30): consent-текст обов'язковий; сабміт не знятий — success-стан
  проєктувати за нашим каноном A-07 (success-wipe), не вигадувати «як у AIR».
